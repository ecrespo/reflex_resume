## 1. Goal

An exploratory analysis of the GitHub account, presented as one interactive dashboard that fits a
desktop screen: what gets built, at what pace, when, with which technologies and stack, which
engineering profile the commits describe, and which projects carry the most impact. A period
control and a profile select recompute every chart; points, clicks and drill-downs give the
detail.

## 2. Files

| File | Role |
|---|---|
| `web/data/dev_dashboard.json` | Pre-aggregated slices, repo details, profile points, impact ranking (generated by the EDA pipeline) |
| `web/dev_dashboard_data.py` | Loads the JSON once at import time; `get_slice(period, profile)`; short row labels |
| `web/states/dev_dashboard_state.py` | `DevDashboardState`: filters, the slice on screen, drill-downs |
| `web/components/dev_dashboard.py` | Page body: header with filters, KPI strip, five tabs of silverpoint `dashboard` grids |
| `web/web.py` | `dev_dashboard_page` + `app.add_page(..., route="/dev-dashboard-stats")`; one CSS fix (§7) |
| `web/components/navbar.py` | "Dev Dashboard Stats" link in both navbars |

**No live GitHub API call.** The site is exported statically and the unauthenticated API is
capped at 60 requests per hour; the figures are frozen as of `DATA_AS_OF` (2026-10-25).

## 3. Data

### Collection

Every public repository of `ecrespo` (279 of 280; one fork refuses anonymous cloning) and the
eight of the `prismal-ai` organisation were cloned with `git clone --bare --filter=blob:none` —
the commit graph and the directory trees, no file contents — and their history read across every
branch and tag:

- 33,802 unique commits processed;
- 4,020 authored by the account owner, matched on the nine e-mail identities used since 2006,
  merge commits excluded;
- 901 of those are automated publishing (Pelican's "Generate Pelican site", CNAME rewrites,
  "Update static build") and are left out;
- **3,119 hand-written commits** behind every chart. Times are the author's local time as git
  recorded it (Caracas, UTC−4 / UTC−4:30).

### Definitions

- **Technologies** — the file types each commit touched (vendored, compiled and generated paths
  ignored). A commit counts once per technology.
- **Stack** — the components each repository declares in its manifests at HEAD (pyproject,
  requirements, package.json, go.mod, Dockerfiles, CI workflows). `ecrespo.github.io` only stores
  Pelican's output and is tagged Pelican by hand.
- **Profiles** overlap: a commit belongs to every profile its evidence supports.
  - *AI Engineer* — LLM stack in the repository (LangChain / LangGraph, MCP, OpenAI, Anthropic,
    Ollama, Hugging Face), a repository about agents or LLMs, `prismal-ai`, or LangChain /
    LangGraph files.
  - *Full-stack Engineer* — Reflex, React, Vue, Next.js, Vite or Tailwind, or TSX / JSX / Vue /
    CSS / HTML files.
  - *Backend Engineer* — FastAPI, Django, Flask, Pydantic, SQLAlchemy, PostgreSQL, Redis, MongoDB
    or Gin.
  - *DevOps / Platform* — Dockerfiles, compose files, CI workflows, Makefiles, deploy configs.
  - *Data Engineer / Scientist* — pandas, NumPy, Matplotlib, Jupyter, Streamlit, scikit-learn,
    notebooks or CSVs.
  - *Systems & Linux* — Go modules or GTK, Go / shell / Glade files, and vigia-eew (cross-platform
    desktop alerts; its "desktop agent" is not an AI agent).
- **Quadrants** (all time): *depth* = share of all hand-written commits in the profile;
  *momentum* = share of the profile's commits in the last 12 months; *visibility* = repos +
  3 × PyPI packages + 2 × tagged repos + stars + forks over the profile's primary repositories,
  scaled so the most visible profile is 100. Cuts: depth 25 %, momentum 65 %, visibility 50.
- **Impact** (0–100) = 30 % commit volume + 20 % active days + 20 % delivery (PyPI, tags, merge
  flow, tests) + 10 % stars and forks + 20 % commits in the last 90 days, each log-scaled to the
  leader. Prismal's eight repositories, the Reflex components and the LangChain / LangGraph labs
  count as one project each. *Trajectory* compares the last 90 days with the 90 before:
  accelerating, active, maintained (quiet for 90 days) or dormant (quiet for a year).

### Slices

`dev_dashboard.json` holds one slice per period × profile (5 × 7 = 35):

- Periods: All time, Past year, 2025–26, 2020–24, 2006–19.
- Profiles: All profiles plus the six above.

A slice carries `kpis`, `monthly`, `yearly`, `weekly` (last 52 weeks of the period), `weekday`,
`hours`, `heatmap` (7 × 24) + `heatmap_max`, `day_sizes`, `repos` (top 25), `tech`, `tech_tree`,
`stack`, `stack_categories` and `profile_mix`. A filter change is a dictionary lookup on the
backend; only the slice on screen is state.

## 4. Page

- **Header (one line):** title, source note, period control (`sp_segmented`), profile select
  (`sp_select`), Reset.
- **KPI strip:** commits, active days, repositories, streak, commits per active day, weekend
  share, peak hour, Conventional Commits share (`sp_statistic`, `size="sm"`).
- **Tabs** (`sp_tabs`; only the open tab mounts its charts). Each is a 2-row grid,
  `row_height=280`, `gap=12`:

| Tab | Charts | Interaction |
|---|---|---|
| Activity | `line_chart` monthly, `bar_chart` yearly / weekly / active-day sizes | filters |
| Rhythm | `bar_chart` weekday + hours, `heatmap_chart` weekday × hour | `link="day"` marks a day in the bars and the grid |
| Repositories | `bar_chart` rows (top N, `sp_slider` 5–25) | `on_select` opens `sp_descriptions` + monthly `line_chart` of that repo |
| Technology & stack | `squarified_treemap`, `donut_chart` categories, `bar_chart` tech + stack (top 12) | a click on a technology opens its group (`root_id` / `on_root_change`) |
| Profiles & impact | `bar_chart` profile mix, 2 × `bubble_chart` quadrants, `bullet_chart` impact (top 8, marker at the median project) | profile select filters the impact ranking |

Charts, ids and props were chosen and checked with the silverpoint MCP (`recommend_chart`,
`get_chart`, `validate_props`, `render_chart`) against reflex-silverpoint-react 0.8.1.

## 6. Layout

- The page body uses tighter padding than the other pages and a `max-w-[1800px]` container.
- The header controls are one block that never wraps internally; it drops under the title only
  on narrow screens.
- The `dashboard` grids use `label` (no visible heading; the tab names them).
- The repository detail scrolls inside its own column, so the page never grows.

## 7. Found during implementation

- **Filters need the backend.** The exported page shows the all-time slice from the state
  defaults; a filter change is a backend event, so it works only while `api.seraph.to` answers.
  The backend must be redeployed before the filters work in production.
- **Row labels (upstream limitation).** silverpoint 0.8.0 draws the categories of a row-oriented
  `bar_chart` (also `lollipop_chart`, `dumbbell_chart`, `error_bar_chart`) in a fixed 56 px column
  (`ROW_LABELS`), so names longer than about nine characters run into the bars. Every row carries
  a short `label` (`dev_dashboard_data.short_label`: aliases such as "Fullstack", "LangGraph",
  "Actions"; prefixes `reflex-` → `rx-`, `python-` → `py-`; then truncation with "…") and the
  full name stays in the tooltip and the drill-down. `bullet_chart` writes each title above its
  bar at full width, which is why the impact ranking uses it. The lasting fix is upstream: size
  the label column from the longest label, as `diverging_bar_chart` already does.
- **`squarified_treemap` drill-down by leaf.** A click sends the clicked node's id; a technology
  is a leaf, and a leaf drawn as the root fills the frame with one cell. `set_tech_root` opens the
  leaf's parent group instead, and only for groups with two or more technologies. The treemap
  also gives the paper (unhatched) tone to the second-largest node, by design of the tone scale.
- **silverpoint 0.8.0 class collision (upstream).** The charts' screen-reader table and
  `SpTable`'s wrapper share the class `sp-table`; `grounds/dist/styles.css` sets
  `.sp-table th, .sp-table td { text-align: right }`, which right-aligns every `SpTable` cell and
  defeats `align: "start"`. `web/web.py` restores `text-align: start` on `.sp-ui-table` cells not
  marked `end` / `center`. The fix belongs in silverpoint (rename one of the two classes).
- **Week labels.** Weekly rows carry a short `week` label ("Oct 27") and the ISO date in `start`
  (used in the tooltip), so 52 bars stay legible.
