I have used `dnsmasq` as a `dns cache` for `opendns` queries or for Google's DNS.

The previous articles that talk about `dnsmasq` are:

1. [Using dnsmasq as a cache and local DNS server](/blog/linux-dnsmasq)  
2. [Improving DNS query speed with dnsmasq and running diagnostic tests](/blog/consultadns1)   

And now DNSCrypt will be used, as shown in the following articles:

1. [Encrypting DNS traffic on Linux with DNSCrypt and OpenDNS](/blog/cifrareltraficodednsenlinuxcondnscryptyopendns)   
2. [Encrypting DNS traffic on Debian 9 Stretch (2017 update)](/blog/cifrareltraficodednsendebian9stretchactualizacion2017) 

To start, `dnsmasq` will be installed:
```
#apt-get install dnsmasq 
```

`DNSCrypt` listens on the IP 127.0.2.1 on port 53; in the case of dnsmasq, it will listen on the IP 127.0.0.1 and port 53 to avoid conflicts between both applications.

Edit the `/etc/dnsmasq.conf` file :
```
#vim /etc/dnsmasq.conf

#Realizar consultas de dominios completos solamente.
domain-needed
#Evitar busquedas internas de dominios locales
bogus-priv
#Habilita dnssec en dnsmasq
proxy-dnssec
#No tomar en cuenta el contenido del archivo /etc/resolv.conf
no-resolv
#Se escucha el servidor de nombres de dnscrypt
server=127.0.2.1
#Evitar ataques de dns rebinding
stop-dns-rebind
#evitar que servidores resuelvan consultas localhost
rebind-localhost-ok
#Se reciben consultas a dnsmasq en 127.0.0.1
listen-address=127.0.0.1
#No se habilita las interfaces para dhcp
no-dhcp-interface=wlp1s0,enp2s0,lo
#Sólo se realizan busquedas de direcciones que está resolviendo.
bind-interfaces
#No tomar en cuenta los hosts del archivo /etc/hosts
no-hosts
#Se define un cache de 500k
cache-size=500
```

Checking the `/etc/resolv.conf` file gives the following:
```
cat /etc/resolv.conf
# Generated by resolvconf

```
Both `dnscrypt` and `dnsmasq` are being used to resolve DNS queries.
